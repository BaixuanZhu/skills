## 三、关键发现

1. **三个真实场景升级全部实测生效**：N1 精确复现「默认闭环 + feedback 分类 + issue 转候选停下裁决 + 留痕」；N2b 精确复现「跨仓库交接契约段 H-001 + 交接文档位置」；N3 精确复现「需求探索六项 + 只写范围不写实现」；N4 精确复现「decision 停下裁决 + .done 留痕保护」。
2. **skill 增量清晰**：baseline 普遍"专业但缺机制"——无留痕约定、无交互裁决（静默落盘/打标）、交接靠执行计划无契约产物、无显式需求探索。with_skill 一致补齐机制层。
3. **边界行为正确**：N2 首测暴露"容量不足时跨仓库依赖组未入选 → 交接契约段不生成"（正确：交接点只在入选任务间存在）；补测 N2b 验证生成路径。
4. **「不写实现」基线也会做**：N3 baseline 同样避开框架/SQL 建议——与 java-coding-guide-pro 达尔文结论一致，skill 增量在「探索机制 + 决策问询纪律 + 缺项待确认」，而非「防写实现」本身。
5. **回归零回退**：v4.4.1 的既有行为（选择题画像/文档优先/MoSCoW/容量确认）全部保持，且 .done 检测正确升级为激活第 1 步。

## 四、遗留

- 无 P0/P1 级缺陷。两处可选优化（未采纳，留档）：① N2 交接点识别可加"容量不足导致依赖组部分入选"的提示（当前行为正确，但可向用户显式说明"依赖组未完整入选，交接点顺延"）；② N3 baseline 的"异步生成"类验收写法提示需求探索时可给"行为 vs 实现"判别示例。
