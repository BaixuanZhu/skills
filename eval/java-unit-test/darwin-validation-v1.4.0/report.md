## 四、对抗集核心证据（两 agent 独立命中 + 仲裁核实）

对抗集是本次验证的核心。三条反馈的根因是否真被修掉，全部经"两 agent 独立判断 + 仲裁文本核实"三层确认：

### T9（反馈1：表格型 VO 逐列断言）

| 版本 | 断言库策略原文 | agent 行为 | 判定 |
|---|---|---|---|
| v1.3.2 | `SKILL.md:38`「同一对象需要 3 个及以上字段断言 → `extracting(...).containsExactly(...)`」+ L41「升级标准：数字段数」 | 16 列 ≥ 3 → **机械触发升级**，建议 `extracting(16 fields).containsExactly(16 values)` | ❌ 功能性缺陷（失败时不知哪列错、顺序敏感、加列要改两处） |
| v1.4.0 | `SKILL.md:39`「字段分组断言（同一逻辑组，如坐标 x/y/z、时间窗 start/end）」+ L41「各列语义独立的逐列断言如表格型 VO 一律 JUnit 原生」 | 16 列语义独立、非同一逻辑组 → **不触发升级**，正确留在原生逐列断言 | ✅ 正确拦截 |

> 集合断言子问题（T9b：list 顺序校验）两版都正确升级到 AssertJ——证明"砍阈值≠砍集合断言"，收窄没误伤。
