# 评分标准（v3.6.0 达尔文盲评用）

> 你是独立盲评 agent。你**不知道**两个版本哪个是旧/新，也**不知道**技能的修改历史。**只根据手里拿到的技能内容，对每个 test-prompt 给出判断。**
>
> 本次是 **v3.5.0 → v3.6.0** 的回归 + 对抗验证。共 14 条 prompt：T1-T8 回归集（沿用上两轮，确保「推荐示例」节删除与 09 精简没让原场景退步）、T9-T14 对抗集（直击本轮五类改动根因）。

## 9 维度评分（SkillLens 风格，满分 100）

每个维度 0–12 分（D9 为 4 分），按"agent 拿着这套技能执行 prompt，能否产出合格结果"打分：

| 维度 | 权重 | 判分锚点 |
|------|------|---------|
| D1 触发精度 | 12 | 描述里的关键词/场景，能否让 agent 在该用时用、不该用时不用 |
| D2 可发现性 | 12 | 想找的信息（命令/规则/范例），在合理跳转步数内能找到 |
| D3 覆盖完整 | 12 | prompt 涉及的知识点，技能是否有答案（无盲点） |
| D4 可执行性 | 12 | 给出的命令/代码/判据，agent 能否直接照做（不悬空、不模糊） |
| D5 防错/陷阱 | 12 | 隐蔽坑（不 fail loud 的错）是否点名 |
| D6 信息密度 | 12 | 有无冗余表达/重复内容/纯说理段落/无行动的出处标注拖累 agent |
| D7 内部导航 | 12 | 路由表/交叉引用是否清晰，agent 知道下一步看哪 |
| D8 范围明确 | 12 | 不适用场景是否声明（不让 agent 越界） |
| D9 整体一致性 | 4 | 术语/规则是否前后一致、无自相矛盾 |

## 回归集（T1-T8）判分要点

这 8 条覆盖 12 个域的核心 antipattern，与上两轮完全相同。重点：**本轮改动（八个 reference 删除「推荐示例」尾节、09 大幅精简、11 新增常量规则、Sonar 规则号删除）是否让这些原场景退步**。若某 prompt 在两版下打分相同，属正常（说明改动没碰该场景）；若某版更低，**必须**给出具体退步证据（行号）。

**特别盯**：
- T2（集合）：`ListUtil.partition` 的「CollUtil.partition 不存在」警告是否仍可查（速查表或 antipattern 2 任一处）。
- T4（HTTP/JSON）：04 的 OkHttp 客户端单例 + 超时示例是否完整（上轮验证过的点不能退）。
- T5（线程池）：手写有界线程池 + 命名工厂 + 优雅关闭的完整代码是否仍在 05（antipattern 6 节，不是被删的「推荐示例」节）。
- T6（BigDecimal）：`divide` 必须显式 scale+RoundingMode、`compareTo` vs `equals`、千分位格式化写法是否可查。
- T8（异常/日志/随机）：随机数当序号的「唯一性由发号器承担」判据是否仍在。

## 对抗集（T9-T14）判分要点

对抗集的目标是**验证本轮改动是否引入功能性缺陷，或修掉旧版的问题**。判分时尤其关注：**一版在该场景下会给出错误/误导/低效建议，另一版能正确处理。**

### T9（「推荐示例」节删除后独有判据是否迁移）

**正确回答应当**：① `subAfter` 第三参 `isLast`（或 `isLastSeparator`）：`true` 取**最后一个**分隔符之后的内容，取扩展名用 `StrUtil.subAfter(fileName, ".", true)`；② `BeanUtil.copyProperties(source, target, CopyOptions.create().ignoreNullValue())`；③ `String.format(Locale.US, "%,.2f", bd)`（显式 Locale 防欧洲逗号小数点）；④ `String.format` 带 Locale 做数字/货币格式化**允许**、做 `%s` 字符串插值**禁用**（该场景用 `StrUtil.format("{}")`）。

**两版预期差异**：一版这四条判据分散在文件尾部的「推荐示例」代码块注释里；另一版把它们折入了开头的规范速查表（① subAfter 行内注第三参语义 / ② 速查表新增「拷贝到已有对象（忽略 null）」行 / ③④ 速查表千分位行 + 紧随的 String.format 边界 blockquote）。查表即得的一版 D2/D6 应更高。**任何一版若四条判据中任一条在全文件查不到（速查表与示例节都没有）→ D3/D4 重扣。**

### T10（09 精简后门控与迁移的 antipattern 是否仍可查）

**正确回答应当**：① JDK 8 不能用 `var`(10)/`record`(16)/文本块(15)——判据为门控表「目标 JDK ≥ 特性最低版本 → 可用」；② `Stream.toList()` 返回**不可变**列表，`add` 抛 `UnsupportedOperationException`，需可变用 `Collectors.toList()`；③ JDK 25 用 `ScopedValue`（不可变、作用域绑定、免 remove），对比表在 05-concurrency「Scoped Values」节；④ JDK 21 虚拟线程遇 `synchronized` 钉住载体线程（改 `ReentrantLock`），JDK 25（JEP 491）解除——依据 09 的 synchronized 陷阱 antipattern 与 05 的对应段。

**两版预期差异**：一版 09 自带「Stream.toList 不可变」「ScopedValues vs ThreadLocal」antipattern 与按版本的通用语法示例（var/switch/文本块/record/instanceof/sealed/虚拟线程各一段）→ 在 09 文件内一步可查但文件显著更长；另一版 09 只留门控表 + 3 个 antipattern + JDK 25 新特性示例，②③ 需跳 02/05 查——判据**仍可查**但入口多一跳：D2 视跳转可达性打分，D6 应给更精简的一版更高分。**若精简版任何判据在全部文件里都查不到 → D3/D5 重扣。**追问 JDK 25 的 Class-File API / Compact Object Headers 等 JVM 内部特性时，只有带完整特性表的版本能答——按实际可查性打分即可，不预设这是缺陷。

### T11（常量与字面量新规则）

**正确回答应当**：`"PENDING"` 出现 ≥2 处 → 必须提取：状态/类型码 → **枚举**（`OrderStatus.PENDING`）；阈值/配置 → 常量类（`OrderConstants.MAX_RETRY`）。常量放置按共享范围判：仅本类 → `private static final`；同包多类 → 包级常量类；跨包 → 按域拆分的常量类；有限取值且有语义 → enum；随环境变化 → 配置文件/配置中心。**禁 `Constants` 万能类**（所有域常量堆一起，改一处全量重编译）。常量类加 `private` 构造禁实例化。

**两版预期差异**：一版只有「魔法值直出 → 抽 static final 常量或枚举」单行规则——能答"要提取"但答不出**何时必须提**（≥2 处判据）、**放哪**（五级放置判据）、**万能类行不行**（禁令）三问 → D3/D4 扣。另一版有专门两条规则 + 放置判据表 + SKILL 路由行与自检项 → 机械可执行 → 高分。

### T12（Sonar 规则号删除后规则本体是否存活）

**正确回答应当**（只验证本体，不要求规则号）：① 无用 import 四类（未使用/重复/java.lang/同包）+ 「删掉某类最后一处使用时同步删 import」；② 认知复杂度阈值 **15**，超标用卫语句/提炼语义方法/分支分发重构；③ `SimpleDateFormat` 非线程安全，static 共享多线程数据错乱，替代 `DateTimeFormatter`（线程安全）或 Hutool `DateUtil`；④ `Math.abs(Integer.MIN_VALUE)` 仍为负（溢出返回自身），转 long 或 `Math.absExact`；⑤ 裸 `now()` 隐式依赖 JVM 默认时区（容器常 UTC），显式传 `ZoneId`/`Clock`；⑥ finally 抛异常会**掩盖** try 块原始异常，禁在 finally 里 return/throw。

**两版预期差异**：两版规则本体都应完整可查（分布在 11/12/05/03/10/08 对应节）。一版在标题/行内附带 Sonar 规则号（S1128/S3776/S6373/S2133/S8688/S1181）——对编码 agent 无行动价值的门禁工具元数据 → D6 微扣；另一版无号、本体完整 → D6 微升。**任何一版本体缺失 → D3/D5 重扣。**

### T13（编号顺移与交叉引用完整性）

**正确回答应当**：① 12-complexity 引用 11 的「复杂布尔表达式先赋具名变量」→ 11 里存在同名规则节（超 3 个逻辑子条件必须拆）；② 05 说 synchronized 陷阱「详见 09」→ 09 存在「虚拟线程 + synchronized 的 LTS 版本陷阱」antipattern（JDK 21 pin / 25 解除）；③ SKILL 路由表「常量与字面量」→ `references/11-conventions.md`，其中有「常量与字面量」节（含提取判据与放置规则）；④ 11 规则编号 §1 起连续无断号。

**两版预期差异**：两版交叉引用都应可解析。一版 12 用**纯编号**引用 11（「第 N 条」）——11 内部规则增删后编号即错位，脆弱；另一版用**规则名**引用——抗重排。D9 给语义引用的版本更高。**若任何一版存在指向不存在标题/编号的悬空引用 → D7/D9 重扣。**

### T14（示例删除后的综合可执行性——兜底验证）

**正确回答应当**：五块全部可查到可直接照抄的写法——判空守卫（`CollUtil.isEmpty`/`isNotEmpty`）；分块（`ListUtil.partition(list, 100)`，注意在 `ListUtil` 非 `CollUtil`）；手写有界线程池（核心/最大/有界队列/命名 ThreadFactory/拒绝策略/`shutdown`+`awaitTermination`/单任务异常隔离记日志）；金额（`new BigDecimal("...")` 构造、`multiply` 后 `setScale(2, RoundingMode.HALF_UP)`、`compareTo` 比较）；拷贝（`BeanUtil.copyProperties(source, target, CopyOptions.create().ignoreNullValue())`）。

**两版预期差异**：预期持平——被删的「推荐示例」节是 antipattern/速查表的复述，正片仍在。若某版五块中任一块（尤其线程池完整形态、拷贝忽略 null）在全部文件查不到可照抄代码 → D4 重扣。这题是「删示例」改动的前后兜底：两版都完整 = 删除无损失；新版缺块 = 删错了。

## 打分输出格式（每个 prompt 必填）

```
### Prompt Tx（一句话场景描述）
- 拿到的技能：版本 [1|2|A|B]（按快照 frontmatter 的 version 字面值）
- D1: x  D2: x  D3: x  D4: x  D5: x  D6: x  D7: x  D8: x  D9: x
- 该 prompt 小计: xx/100
- 关键依据（≤3 条，引用具体行号或代码块）:
  1. ...
  2. ...
  3. ...
- 扣分主因（这个 prompt 在这个版本下最大的失分点）:
```

**铁律**：
- 每条依据必须能指向技能里的具体位置（行号 / 标题 / 代码块）。禁止泛泛说"覆盖全面"。
- D6（信息密度）：冗余越多扣分越重。与正文重复的「推荐示例」尾节、无行动价值的 Sonar 规则号标注、复述性散文 → 扣分。
- D4（可执行性）：规则只有断言没有可照抄代码、判据需要多行串联心算 → 扣分。
- **对抗集特别规则**：若某版本在该 prompt 下会给出**错误或误导建议**（判据丢失 / 引用悬空 / 该有的代码块从全部文件消失），这是**功能性缺陷**，相应维度（D2/D3/D4/D5/D7）应重扣（≤4 分），不能因"文字通顺"给中庸分。
- 不要因为版本号高低影响打分。版本号是元数据，与内容质量无关。
- 你不知道拿到的版本哪个是旧/新，按你看到的版本字面值打分即可，不要猜。
- **方法节必填**：报告开头粘贴你实际拿到的两个快照目录的 frontmatter `version:` 字面值，作为配对证据。
