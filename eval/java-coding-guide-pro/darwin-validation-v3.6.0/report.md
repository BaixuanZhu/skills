## 五、对抗集核心证据（仲裁全量核实，0 虚构）

- **T9（判据迁移）**：v3.5.0 的 subAfter 第三参 / ignoreNullValue / 千分位 Locale.US / String.format 边界四条独有判据埋在文件尾「推荐示例」代码注释；v3.6.0 分别迁入 01 L21 / 06 L15 / 10 L18+L20 速查表——查表即得，无需翻到文件尾。
- **T11（常量规则）**：v3.5.0 仅 SKILL L127「魔法值直出→抽 static final 或枚举」单行 + 11 §8；「建 Constants 类行不行」「放哪」「何时必须提」三问无判据。v3.6.0 新增 11 §9（L92-104，≥2 处机械判据 + 与 prompt 同构的 "PENDING" 双类示例）+ §10（L106-131，五级放置表 + 禁万能类 + private 构造），SKILL L93 路由词 / L128 规则行 / L162 自检项三处联动——从「答不出」到「机械可执行」。
- **T13（引用语义化）**：v3.5.0 的 12 L133「第 15 条」、05 L162「antipattern 3」纯编号引用，重排即错位；v3.6.0 全部语义化且 11 §1-21 连续（1-7 命名、8-11 常量、12-16 OOP、17-18 控制、19-21 格式），全套无悬空引用。

## 六、透明记录：T10 负项裁决与唯一实质缺口

1. **T10（−2/−4，唯一负差值）**：退步方向成立——09 精简后 toList 不可变、ScopedValue 需跳 02/05 查（判据零缺失，入口多一跳）；`UnsupportedOperationException` 异常名与「JDK 8 等价写法」可照抄性小损。仲裁裁 **−2~−3 属设计预期**（密度换直达性，B 的 D3 扣分偏严），非阻断。
2. **05 TaskRunner 异常隔离（唯一实质缺口，非阻断）**：v3.5.0「推荐示例」里 `submit 内 catch (Throwable)` 单任务异常隔离整块在 v3.6.0 全套**无整块承接**（最近似物 05 L143 exceptionally）——但要素可由 05+08 拼装，rubric D4 重扣条件（整块查不到）不满足。**仲裁补充发现**：被删的 `catch (Throwable)` 本与 SKILL L111「禁 catch (Throwable)」S 级规则表面矛盾，删除反而消除了一处不一致（D9 隐藏收益）。建议 v3.6.x 以 `catch (Exception)` 形态回补三行。
3. **09 五个 ⚠ JVM 特性行（Class-File API / Compact Object Headers / Compact Source Files / Module Import Declarations / KDF）无承接**：属覆盖面有意收窄（rubric 明示不预设为缺陷）；HttpClient 行的 OkHttp 取向判据有承接（SKILL L84 + 04 L6 + 构件表）。
4. **配对零缺陷**：两份盲评方法节均正确粘贴 frontmatter version 字面值（上轮 blind-B 标签写反的改进项生效）。
