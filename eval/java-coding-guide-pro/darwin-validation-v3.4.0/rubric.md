# 评分标准（v3.4.0 达尔文盲评用）

> 你是独立盲评 agent。你**不知道**两个版本哪个是旧/新，也**不知道**技能的修改历史。**只根据手里拿到的技能内容，对每个 test-prompt 给出判断。**
>
> 本次是 **v3.3.0 → v3.4.0** 的回归 + 对抗验证。共 11 条 prompt：T1-T8 回归集（确保精简没让原场景退步）、T9-T11 对抗集（直击本次五类问题的根本原因）。

## 9 维度评分（SkillLens 风格，满分 100）

每个维度 0–12 分（D9 为 4 分），按"agent 拿着这套技能执行 prompt，能否产出合格结果"打分：

| 维度 | 权重 | 判分锚点 |
|------|------|---------|
| D1 触发精度 | 12 | 描述里的关键词/场景，能否让 agent 在该用时用、不该用时不用 |
| D2 可发现性 | 12 | 想找的信息（命令/规则/范例），在合理跳转步数内能找到 |
| D3 覆盖完整 | 12 | prompt 涉及的知识点，技能是否有答案（无盲点） |
| D4 可执行性 | 12 | 给出的命令/代码/判据，agent 能否直接照做（不悬空、不模糊） |
| D5 防错/陷阱 | 12 | 隐蔽坑（不 fail loud 的错）是否点名 |
| D6 信息密度 | 12 | 有无冗余表达/重复内容/纯说理段落拖累 agent |
| D7 内部导航 | 12 | 路由表/交叉引用是否清晰，agent 知道下一步看哪 |
| D8 范围明确 | 12 | 不适用场景是否声明（不让 agent 越界） |
| D9 整体一致性 | 4 | 术语/规则是否前后一致、无自相矛盾 |

## 回归集（T1-T8）判分要点

这 8 条覆盖 12 个域的核心 antipattern。重点：**v3.4.0 五类改动（悬空引用修复 / 删「强约束提醒」节 / 精简重述引用块 / 跨文件去重 / S/A 表 why 列精简）是否让这些原场景退步**。若某 prompt 在两版下打分相同，属正常（说明改动没碰该场景）；若 v3.4.0 更低，**必须**给出具体退步证据（行号）。

**特别盯**：
- T2（集合 subList/分块）：原「强约束提醒」含 `CollUtil.shuffle 不存在` 独有判据——v3.4.0 应已并入 antipattern 2 末尾。若该判据丢失 → D3/D5 扣分。
- T6（金额 BigDecimal）：原「强约束提醒」含 `Math.abs(MIN_VALUE)` + `byte & 0xFF`——v3.4.0 这些判据仍在 antipattern 8/9。若丢失 → D3 扣分。

## 对抗集（T9-T11）判分要点

对抗集的目标是**验证五类问题的根本原因是否被真正修掉**。判分时尤其关注：**v3.3.0（旧版）是否会在这些场景下给出错误或误导建议，而 v3.4.0（新版）能正确处理。**

### T9（根因：悬空引用——MapStruct/OkHttp/Jackson/SLF4J 坐标）

用户问 MapStruct 或 OkHttp3 的 Maven 坐标怎么写、annotation processor 怎么配。

**正确回答应当**：从 SKILL.md「C-CHECK 询问（仅高风险能力缺失时触发）」节的 blockquote 找到坐标（MapStruct 1.5.5.Final / OkHttp3 4.12.0 / Jackson 2.17.1 / SLF4J 2.0.13 + Logback），或从对应 reference（04/06/07/08）的指针跳到该节。

**两版预期差异**：
- **v3.3.0**：references 04/06/07/08 写「坐标见 SKILL.md「必选依赖」/「依赖坐标」」——但 SKILL.md **没有这两个节**（坐标在「C-CHECK 询问」节的 blockquote）→ agent 走断链，找不到坐标 → D2/D4/D7 重扣（功能性缺陷）。
- **v3.4.0**：所有指针改为「C-CHECK 询问（仅高风险能力缺失时触发）」——该节**真实存在**，blockquote 含坐标 → agent 一跳到位 → 高分。

**判分锚点**：若版本下 agent 按指针走不到坐标（指了不存在的节名）→ D2/D4/D7 重扣（≤4 分）。指针指向真实存在的节 → 高分。

### T10（根因：删「强约束提醒」节后规则是否仍可查——BigDecimal 除法/比较）

用户问 BigDecimal 除法怎么写、为什么 equals 比较有问题。

**正确回答应当**：从 reference 10 的「规范速查」表 + antipattern 3（除法 ArithmeticException）+ antipattern 4（equals 比 scale）找到完整规则——「除法必须给 scale + RoundingMode，禁裸 divide」「比较用 compareTo == 0，禁 equals」。

**两版预期差异**：
- **v3.3.0**：规则在速查表 + antipattern + 末尾「强约束提醒」三处（冗余但都在）。
- **v3.4.0**：删了「强约束提醒」，规则仍在速查表 + antipattern——**应不退步**（速查表 + antipattern 已完整覆盖）。若 v3.4.0 让某条判据丢失（如 `Math.abs(MIN_VALUE)` 只在「强约束提醒」有、antipattern 没有）→ D3 扣分。

**判分锚点**：能从速查表/antipattern 完整找到规则 → 高分。判据丢失 → D3 扣分。v3.4.0 删冗余节本身不扣分（D6 反而应微升，信息密度更高）。

### T11（根因：跨文件去重——JDK 25 ScopedValue 完整 API 在哪）

用户在 JDK 25 项目问 ScopedValue 怎么用（基本用法 + 嵌套绑定 + 与 ThreadLocal 对比表）。

**正确回答应当**：定位到 `references/05-concurrency.md`「Scoped Values」节——含完整 API（基本用法、嵌套绑定示例、对比表）。09 的 antipattern 4 只是一行 ✗/✓ 对照 + 指针。

**两版预期差异**：
- **v3.3.0**：05 有完整 API + 对比表；09 antipattern 4 **也重复贴了完整代码 + 解释**（跨文件冗余）——两处都能答，但 D6（信息密度）应因冗余扣分。
- **v3.4.0**：05 仍是真值源（完整 API + 表）；09 antipattern 4 精简为一行对照 + 指针「详见 05」——agent 从 09 跳到 05 能找到完整答案，且无冗余 → D6/D7 更优。

**判分锚点**：能定位到 05 完整 API → 高分。若 v3.4.0 误删了 05 的 API（真值源丢了）→ D3 重扣。若 09 仍整段重复 → D6 扣分（冗余未去）。

## 打分输出格式（每个 prompt 必填）

```
### Prompt Tx（一句话场景描述）
- 拿到的技能：版本 [A|B]
- D1: x  D2: x  D3: x  D4: x  D5: x  D6: x  D7: x  D8: x  D9: x
- 该 prompt 小计: xx/100
- 关键依据（≤3 条，引用具体行号或代码块）:
  1. ...
  2. ...
  3. ...
- 扣分主因（这个 prompt 在这个版本下最大的失分点）:
```

**铁律**：
- 每条依据必须能指向技能里的具体位置（行号 / 标题 / 代码块）。禁止泛泛说"覆盖全面"。
- D6（信息密度）：冗余越多扣分越重。读到「强约束提醒」节逐字复述上方表、`> 为什么` 重述代码已表达的规则、跨文件整段重复 → 扣分。
- D4（可执行性）：指针指了不存在的节名（悬空引用）→ 重扣（agent 走断链）。
- **对抗集（T9/T10/T11）特别规则**：若某版本在该 prompt 下会给出**错误或误导建议**（如指针走断链找不到坐标 / 规则判据丢失 / 真值源被误删），这是**功能性缺陷**，相应维度（D2/D3/D4/D7）应重扣（≤4 分），不能因"文字通顺"给中庸分。
- 不要因为版本号高低影响打分。版本号是元数据，与内容质量无关。
- 你不知道 A/B 哪个是 v3.3.0 哪个是 v3.4.0，按你看到的版本字面值打分即可，不要猜。
