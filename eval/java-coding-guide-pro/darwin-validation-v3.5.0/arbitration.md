## 二、标签映射复核（blind-B 已知异常）

**事实**：blind-B 自述「versionA = 3.4.1，versionB = 3.5.0」，与实际目录相反（versionA=3.5.0、versionB=3.4.1）。

**判定方法**：若 blind-B 实际把目录 versionA 当作「A」评，其「A」引用应命中 v3.5.0 内容；反之则命中 v3.4.1 内容。核验结果（全量、无一例外）：

- 所有「versionA」引用命中 **v3.4.1（旧）独有内容**：`04:68` 无超时示例、`SKILL:143` S3252、`01:117-125`/`01:4`/`01:125`、`11:291` IDE 指引、`11:1-4` 出处行、`05:229-231` Guava 段、`SKILL:43-51` 五档、`SKILL:141` 一行 prose——这些内容在 v3.5.0 中均不存在（部分行号越界，如 v3.5.0/11 仅 288 行、05 仅 228 行、01 仅 115 行）。
- 所有「versionB」引用命中 **v3.5.0（新）独有内容**：`04:67/:70-73` 超时、`SKILL:49/:51-61/:63` 新门控、`SKILL:147-153` 构件表、`11:278-288` 无 IDE、`SKILL:18-19` 任务词、「01 止于 :115」「grep 无 S3252」。

**结论**：blind-B 评的是「标签 A = 旧内容（v3.4.1）、标签 B = 新内容（v3.5.0）」——与 blind-A 的（version1=旧 / version2=新）配对方向一致。**其评分配对有效**：汇总表中「versionA 小计 1231」实为旧版总分、「versionB 小计 1287」实为新版总分，可直接与 blind-A 的 1263/1315 对齐比较。

**如实记录的缺陷**：blind-B 报告的方法节自述读取了 `snapshots/versionA/`、`snapshots/versionB/` 且 frontmatter 为 A=3.4.1/B=3.5.0——该陈述与实际目录 frontmatter 相反，说明它要么把两个目录的内容-标签整体对调后评写、要么未实际读取其所声称目录的 frontmatter。这是盲评协议的标签记录缺陷（方法节自述不可信），但因（a）全部证据真实且配对方向经全量核验、（b）评分锚定在引用证据而非版本号、（c）blind-A 以正确映射独立覆盖同一内容，不构成评分无效事由。后续轮次应要求盲评 agent 在报告中粘贴 frontmatter 原文以防此类对调。

## 三、T11 分歧裁决（S3252 段删除）

**分歧**：blind-A 判新版 +1（旧 90 / 新 91）；blind-B 判旧版 +2（旧 89 / 新 87，B 认为保留 S3252 段能回答门禁追问）。

**两版相关内容（已核）**：
- 旧：SKILL.md:143 尾注 blockquote（含条件分支与两套处置）+ 01:117-125 完整节（事实背景「StrUtil 继承 CharSequenceUtil 会命中 S3252」/ 默认保留 StrUtil / 门禁阻断时二选一：标 Accepted 或配例外（推荐）、全局换 CharSequenceUtil；禁混用、禁逐处 NOSONAR / 同类门面同策略）。

**逐路径净影响**：

1. **「写判空」主路径（高频）**：两版默认均唯一为 StrUtil（旧版 S3252 节自己也写「默认继续写 StrUtil，不主动改写」），agent 生成判空代码只读 01:10 即得答案，旧版的条件分支位于文件尾与 SKILL 尾注，不污染速查表。故删除对主路径**无质量损失**，仅有小的密度收益（新版 D6 满分合理）。blind-B 在 T1 也承认旧版「判空默认本身未受影响」——其 T11 给旧版 D6=9 的重罚与自己在 T1 的判定不完全自洽。
2. **「门禁追问」边缘路径（T11 第二问原文明确问到）**：旧版技能内有可机械执行的处置流程（推荐路径+两条禁令）；新版技能内无答案，agent 只能答「超出技能范围」或临场发挥。rubric 明文：「该知识不属于编码指南职责……无该节的版本答不出技能内方案不扣重分」。故此处对新版是**轻扣（D3 层面）而非重扣**。blind-B 对新版同时扣 D3 −2、D5 −2、D2 −1（合计 −5 对抗 D6 +3），其中 D5/D2 两处实质是对 rubric 明示免责的项重复计罚；另需指出一个被 blind-B 部分捕捉的真实点：新版推荐的唯一默认 `StrUtil.isBlank` 本身会触发 S3252 告警——这确是一个「不 fail loud」的坑，新版未作任何提示，D5 小扣（−1 量级）有依据。

**裁决**：删除 S3252 段的净影响 ≈ **中性**（主路径 +1~+2 密度收益，边缘路径 −2~−3 覆盖损失，两向相抵，合理区间 −1~+1）。**blind-A 的 +1 更合理**——它按 rubric 明示口径把门禁追问按「职责外轻扣（仅 D3 −2）」处理；blind-B 的 −2 方向可理解（prompt 确实明确问了），但其扣分结构（D5/D2 同步重罚 rubric 免责项）过重，且与自身 T1 判定略有矛盾。两份评分均在校准噪声内，均不构成需作废的评分错误；T11 取仲裁值 ≈ 0（新版不因该项获得净改进，也不构成退步——这是本轮设计上「两向相抵」的预期结果）。
