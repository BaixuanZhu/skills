# 评分标准（v3.5.0 达尔文盲评用）

> 你是独立盲评 agent。你**不知道**两个版本哪个是旧/新，也**不知道**技能的修改历史。**只根据手里拿到的技能内容，对每个 test-prompt 给出判断。**
>
> 本次是 **v3.4.1 → v3.5.0** 的回归 + 对抗验证。共 14 条 prompt：T1-T8 回归集（沿用上轮，确保三处内容压缩没让原场景退步）、T9-T14 对抗集（直击本轮六类改动根因）。

## 9 维度评分（SkillLens 风格，满分 100）

每个维度 0–12 分（D9 为 4 分），按"agent 拿着这套技能执行 prompt，能否产出合格结果"打分：

| 维度 | 权重 | 判分锚点 |
|------|------|---------|
| D1 触发精度 | 12 | 描述里的关键词/场景，能否让 agent 在该用时用、不该用时不用 |
| D2 可发现性 | 12 | 想找的信息（命令/规则/范例），在合理跳转步数内能找到 |
| D3 覆盖完整 | 12 | prompt 涉及的知识点，技能是否有答案（无盲点） |
| D4 可执行性 | 12 | 给出的命令/代码/判据，agent 能否直接照做（不悬空、不模糊） |
| D5 防错/陷阱 | 12 | 隐蔽坑（不 fail loud 的错）是否点名 |
| D6 信息密度 | 12 | 有无冗余表达/重复内容/纯说理段落/无行动的出处标注拖累 agent |
| D7 内部导航 | 12 | 路由表/交叉引用是否清晰，agent 知道下一步看哪 |
| D8 范围明确 | 12 | 不适用场景是否声明（不让 agent 越界） |
| D9 整体一致性 | 4 | 术语/规则是否前后一致、无自相矛盾 |

## 回归集（T1-T8）判分要点

这 8 条覆盖 12 个域的核心 antipattern，与上一轮（v3.3.0→v3.4.0）完全相同。重点：**本轮改动（删出处引用/IDE 指引/S3252 策略段/Guava 备注、JDK 门控表重写、高风险表压缩、规则表删「为什么」列）是否让这些原场景退步**。若某 prompt 在两版下打分相同，属正常（说明改动没碰该场景）；若新版更低，**必须**给出具体退步证据（行号）。

**特别盯**：
- T1（判空/Optional）：一版 01 文件曾含「Sonar S3252 与 StrUtil」节——若某版删了该节，判空主路径（规范速查表）**不受影响才算没退步**；若删除导致「用 StrUtil 还是 CharSequenceUtil」失去唯一默认 → D4 扣分。
- T4（HTTP/JSON）：注意 04 的 HTTP 节有没有「客户端必须显式设置连接/读超时」的规则与示例——缺超时规则的一版 D3/D5 扣分。
- T8（异常/日志/随机）：规则表「为什么」列若被删，但技术判据（如随机≠唯一）在对应 reference 仍在 → 不扣分；判据彻底消失 → D3/D5 扣分。

## 对抗集（T9-T14）判分要点

对抗集的目标是**验证本轮改动是否引入功能性缺陷，或修掉旧版的问题**。判分时尤其关注：**一版在该场景下会给出错误/误导/低效建议，另一版能正确处理。**

### T9（出处引用与 IDE 指引删除后规则是否仍可查）

**正确回答应当**：① import 同步删除规则在 SKILL.md 规则表 A 级行（「无用 import…删掉某类最后一处使用时同步删 import」）；② 命名规约在 `references/11-conventions.md` 的 19 条规则里（布尔禁 is 前缀/抽象类 Abstract|Base/异常类 Exception 结尾/常量全大写下划线/long 用大写 L）。

**两版预期差异**：若某版 11 文件用「来源：阿里巴巴 Java 开发手册」等出处行开头、且规则本体完整 → 规则可查性相同，但出处行属无行动信息 → D6 微扣；若某版把 import 同步删除规则从 SKILL.md 规则表弄丢 → D3/D5 重扣。某版含「IDE Optimize Imports（Ctrl+Alt+O）」类 IDE 快捷键指引 → agent 无法执行 → D4 微扣。

### T10（JDK 版本门控判据）

**正确回答应当**：给出每个特性在每档 JDK 的可用性，且判据可机械执行（拿到目标 JDK 一次比较出结果）。JDK 16 应能用 `record`（16 转正）；JDK 21 虚拟线程避免 `synchronized`（钉住），JDK 25 不再钉住。

**两版预期差异**：一版用「五档累加」表述（JDK 11：+ var(10)、HttpClient(11)；JDK 17：+ switch 表达式(14)…）——agent 需自行串联多行才能回答「JDK 17 能用什么」，且档位与括号内实际版本两套编号混排，非 LTS 目标（如 JDK 16）无明确判据 → D4 扣分。另一版若为「特性 → 最低 JDK」平表 + 「目标 JDK ≥ 最低版本 → 可用」单条判据 + 明确「非 LTS 同样按版本比较」→ 一次比较出结果 → D4 高分。

### T11（S3252 策略段删除后的字符串默认）

**正确回答应当**：判空统一用 `StrUtil.isBlank`（Hutool 官方门面，技能全表一致）。

**两版预期差异**：一版在 SKILL.md 与 01 含「Sonar S3252 与 Hutool 门面」策略段——含「仅当项目门禁启用该规则且阻断时，才全局换 CharSequenceUtil 或配置规则例外」的条件分支与多套处置选项 → 对「写判空」这一高频动作引入决策疲劳 → D6 扣分（但若你判它为有效防错信息，可不扣）。另一版只有唯一默认 `StrUtil`、无该规则讨论 → 默认明确 → D4/D6 高分。**注意**：对「Sonar 扫出来了怎么办」的追问，无该节的版本答不出技能内方案不扣重分（该知识不属于编码指南职责），有该节的版本能答 → 两版按实际可查性打分即可。

### T12（高风险表压缩后 C-CHECK 范围 + HTTP 超时）

**正确回答应当**：① 仅「加密/哈希/密码」与「Bean 映射」两类在项目缺能力时触发 C-CHECK 询问；低风险（判空/集合/随机/日期）永不询问；② OkHttp3 客户端单例复用 + 显式 `connectTimeout`/`readTimeout`，规则与示例在 `references/04-io-http-json.md` HTTP 节。

**两版预期差异**：一版把「HTTP 调用｜连接泄漏、超时缺省」放在 SKILL.md 高风险表的「为什么手写危险」列，但 04 的 OkHttp 示例**没设任何超时**——「超时必设」只有断言没有落地代码 → D4/D5 扣分。另一版 04 的 OkHttp 单例示例含 `.connectTimeout(5, TimeUnit.SECONDS).readTimeout(30, TimeUnit.SECONDS)` + 规则行 → 可直接照抄 → 高分。C-CHECK 触发范围两版应都可查（SKILL.md C-CHECK 节）。

### T13（规则表「为什么」列删除后判据折入是否完整）

**正确回答应当**：六个判据全部可查——① `Calendar` 月份从 0 起；② Spring 与 Apache `copyProperties` 参数顺序相反；③ `randomInt(min, max)` 为 [min, max) 半开不含上界；④ 裸 `now()` 隐式依赖 JVM 默认时区；⑤ S1128（无用 import）；⑥ S3776 认知复杂度阈值 15。

**两版预期差异**：一版规则表带「为什么」列，六判据在列内 → 可查。另一版若删列后判据**折入 ✗/✓ 单元格**（如「Calendar 手算（月份从 0 起）」「RandomUtil.randomInt(min, max)（[min, max) 半开）」）→ 同样可查，且信息密度更高 → D6 微升；若某版删列后判据**彻底消失**（六条中任何一条在 SKILL.md 与全部 reference 都查不到）→ D3/D5 重扣。

### T14（构件版本表与日志门控）

**正确回答应当**：JDK 8 用 SLF4J 1.7.36 + Logback 1.2.x；JDK 11+ 用 SLF4J 2.0.13 + Logback 1.5.x；两套禁混用。MapStruct 1.5.5.Final（需 annotation processor）、Jackson 2.17.1、OkHttp3 4.12.0、Lombok 1.18.34 的版本在 SKILL.md C-CHECK 节可查。

**两版预期差异**：一版把全部版本挤在一行 prose 里、且 SLF4J 只写「2.0.13（JDK 8 用 1.7.36）」**没给 Logback 版本**、无「两套禁混用」警示（Logback 门控要跳到 08 才拼得出全貌）→ D3/D4 扣分。另一版若为小表（构件/版本/门控备注三列，SLF4J+Logback 行含两套组合与禁混用警示）→ 一次查全 → 高分。

## 打分输出格式（每个 prompt 必填）

```
### Prompt Tx（一句话场景描述）
- 拿到的技能：版本 [1|2|A|B]（按快照 frontmatter 的 version 字面值）
- D1: x  D2: x  D3: x  D4: x  D5: x  D6: x  D7: x  D8: x  D9: x
- 该 prompt 小计: xx/100
- 关键依据（≤3 条，引用具体行号或代码块）:
  1. ...
  2. ...
  3. ...
- 扣分主因（这个 prompt 在这个版本下最大的失分点）:
```

**铁律**：
- 每条依据必须能指向技能里的具体位置（行号 / 标题 / 代码块）。禁止泛泛说"覆盖全面"。
- D6（信息密度）：冗余越多扣分越重。出处标注（「来源：XX 手册」）、IDE 快捷键指引、复述性散文、给高频动作引入多选项决策分支 → 扣分。
- D4（可执行性）：规则只有断言没有可照抄代码、判据需要多行串联心算 → 扣分。
- **对抗集特别规则**：若某版本在该 prompt 下会给出**错误或误导建议**（判据丢失 / 超时规则只有断言无落地 / 版本信息不全导致选错依赖组合），这是**功能性缺陷**，相应维度（D2/D3/D4/D5/D7）应重扣（≤4 分），不能因"文字通顺"给中庸分。
- 不要因为版本号高低影响打分。版本号是元数据，与内容质量无关。
- 你不知道拿到的版本哪个是旧/新，按你看到的版本字面值打分即可，不要猜。
