# 评分标准（agile-report 达尔文盲评用）

> 你是独立盲评 agent。你手里有：agile-report 技能（SKILL.md + 4 个 references）、fixture 数据（`eval/agile-report/fixtures/project-root/`）、7 条 test-prompt。
>
> 对每个 prompt，假设你是"接到该请求的 coding agent，手里只有这套技能"，判断能否产出合格结果。按 9 维度打分。

## 9 维度评分（SkillLens 风格，满分 100）

每个维度 0–12 分（D9 为 4 分），按"agent 拿着这套技能执行 prompt，能否产出合格结果"打分：

| 维度 | 权重 | 判分锚点 |
|------|------|---------|
| D1 触发精度 | 12 | description 的关键词/场景，能否让 agent 在该用时用、不该用时不用 |
| D2 可发现性 | 12 | 想找的信息（命令/公式/映射表），在合理跳转步数内能找到 |
| D3 覆盖完整 | 12 | prompt 涉及的知识点，技能是否有答案（无盲点） |
| D4 可执行性 | 12 | 给出的命令/代码/判据，agent 能否直接照做（不悬空、不模糊） |
| D5 防错/陷阱 | 12 | 隐蔽坑（不 fail loud 的错）是否点名 |
| D6 信息密度 | 12 | 有无冗余表达/重复内容/纯说理段落拖累 agent |
| D7 内部导航 | 12 | 路由表/交叉引用是否清晰，agent 知道下一步看哪 |
| D8 范围明确 | 12 | 不适用场景是否声明（不让 agent 越界） |
| D9 整体一致性 | 4 | 术语/规则是否前后一致、无自相矛盾 |

## 各 prompt 判分要点

### T1（完整态·核心路径）—— 重点 D3/D4/D5

最高权重。这是技能的主路径，必须跑通：
- **D3 覆盖**：能否从 fixture 算出正确完成率（85.7%）？点数回读是否正确（59 承诺 / 43 完成）？三态分类是否正确（12 完成 / 2 移出 / 0 未执行）？
- **D4 可执行性**：HTML 生成步骤是否可照做？Playwright pdf 命令是否准确？
- **D5 防错**：是否点到 `--wait-for-timeout` 毫秒坑、Chromium-only、npm 两步装？

**判分锚点**：完成率算错（如漏算 Sprint、id 重复计数）→ D3 重扣（≤4）。命令错误（参数名错、漏 --browser）→ D4 重扣。

### T2（工具链陷阱·对抗）—— 重点 D4/D5

直击 toolchain.md 的核心陷阱知识。这是技能存在的理由之一：
- **D4 可执行性**：命令必须一字不差——`npx playwright pdf --browser chromium --wait-for-timeout 2000 --paper-format A4 <html> <pdf>`
- **D5 防错**：5 大陷阱是否全部点到：
  1. `--wait-for-timeout` 单位是毫秒不是秒
  2. PDF 只有 Chromium 支持
  3. `playwright` ≠ `@playwright/cli`
  4. `npm install` 后还要 `npx playwright install chromium`
  5. ECharts 必须 headless 浏览器渲染

**判分锚点**：漏任何一个陷阱 → D5 扣 2-3 分。命令参数错 → D4 重扣（≤4）。

### T3（降级态·对抗）—— 重点 D3/D8

- **D3 覆盖**：能否说明 git log 解析规则（日期范围、commit message 分类：feat/fix/refactor）？
- **D8 范围**：是否明确说明降级报告的限制（无完成率%、无 Backlog 分布）？
- 是否标注"数据来源：git log（简化版）"？

**判分锚点**：拒绝产出（要求必须先建敏捷文档）→ D3 重扣（技能明确说不拒绝）。未标注数据来源 → D8 扣。

### T4（数据聚合·阻塞项）—— 重点 D3/D4

- **D3 覆盖**：能否识别 T-003 出现在 2 个 Sprint 的 moved_next（阻塞信号）？
- **D4 可执行性**：是否用**表格**呈现（chart-config.md §一 明确移出任务用表格非图表）？

**判分锚点**：漏掉 T-003（只扫单个 Sprint）→ D3 重扣。用饼图/柱状图呈现移出项 → D4 扣（违反 chart-config 选型规则）。

### T5（范围边界·按需衍生）—— 重点 D1/D8

- **D1 触发精度**：技能是否明确自己靠触发词激活，不参与 using-agile 路由？
- **D8 范围**：是否声明是按需衍生，不是流程必须环节？

**判分锚点**：建议"每个 Sprint 自动生成"或"加入流程闭环"→ D1/D8 重扣（与技能定位矛盾）。

### T6（视觉编码·术语映射）—— 重点 D3/D4

- **D3 覆盖**：术语映射表是否完整（故事点→任务量、MoSCoW→核心/次要需求、ADR→技术决策记录、DoD→验收标准、Sprint→迭代周期）？
- **D4 可执行性**：是否说明转换时机（写入 HTML 前强制转换）？配色规则是否明确（红<60/黄60-85/绿>85）？

**判分锚点**：映射表缺条目 → D3 扣。未说明转换时机 → D4 扣。

### T7（一致性校验·边界）—— 重点 D4/D5

- **D4 可执行性**：是否说明校验规则（id 集合 / 条目数 / priority+status 三项）？
- **D5 防错**：不一致时是否停下报告（不静默挑一份算下去）？

**判分锚点**：未说明不一致处理（静默继续）→ D5 重扣（技能明确说不静默）。

## 打分输出格式（每个 prompt 必填）

```
### Prompt Tx（一句话场景描述）
- D1: x  D2: x  D3: x  D4: x  D5: x  D6: x  D7: x  D8: x  D9: x
- 该 prompt 小计: xx/100
- 关键依据（≤3 条，引用技能里的具体位置：行号/标题/代码块）:
  1. ...
  2. ...
  3. ...
- 扣分主因（这个 prompt 最大的失分点）:
- 产出正确性（仅 T1/T4 需填，对照 ground-truth.md）:
  - 完成率计算: ✓/✗ (agent 算出的值 vs 正确值)
  - 点数回读: ✓/✗
  - 阻塞项识别: ✓/✗ (仅 T4)
```

## 铁律

- 每条依据必须能指向技能里的具体位置（行号/标题/代码块）。禁止泛泛说"覆盖全面"。
- **功能性缺陷重扣**：命令错误、完成率算错、漏识别阻塞项 → 对应维度（D3/D4）≤4 分，不能因"文字通顺"给中庸分。
- **陷阱遗漏重扣**：toolchain.md 的 5 大陷阱是技能核心价值，漏任何一个 → D5 扣 2-3 分。
- D6（信息密度）：冗余越多扣分越重。但本技能是新技能（无旧版对比），D6 主要看是否有内部重复（SKILL.md 与 references 重复）。
- 对 T1/T4，必须对照 ground-truth.md 核对产出数值正确性——数值错是硬伤。
