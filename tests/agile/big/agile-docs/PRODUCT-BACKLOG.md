## 任务详情

### T-003 重复订单号改为幂等返回或明确冲突，移除先查后插

- 验收: 同一 orderNo 并发提交 2 次，两次都得到同一笔订单的结果，库中只有 1 条；不出现 500。
- 验收: 真冲突（不同订单撞号）时返回可理解的业务错误并带订单号，响应体不含堆栈。
- 约束: 冲突判定不得依赖"先查后插"的窗口；不引入新中间件。（关联 ADR-003）

### T-008 数据库迁移纳入版本管理，生产 schema 可重建

- 验收: 空库执行迁移得到与生产一致的 schema；生产现有结构纳入基线版本并有对照说明。
- 约束: 迁移向后兼容（先加列、后删列）；每次发布前先备份。（关联 ADR-009）

### T-015 备份与恢复演练，记录实测 RTO/RPO

- 验收: 从最近备份恢复到临时实例，记录实测 RTO/RPO；恢复后订单数与审计数一致。
- 约束: 演练脚本可重复执行，全程不触碰生产库。（关联 ADR-009）

### T-005 订单表补时间字段与查询索引

- 验收: 任意订单可查到创建时间与最后更新时间（带时区）；按时间段查询不出现全表扫描。
- 约束: 存量数据回填需先说明来源，无法确认的标为"未知"而不是用当前时间填充。（关联 ADR-007、T-008）

### T-007 建立测试基线：真实 PG 集成测试覆盖下单主链路

- 验收: `mvn verify` 在本地 Docker 环境跑通，覆盖 4 个场景：下单成功、库存不足、订单号重复、审计必达。
- 约束: 使用真实 PG 而非 H2；主链路测试总耗时控制在分钟级。（关联 ADR-008）

### T-004 库存扣减死锁与瞬时失败有限重试

- 验收: 同一 SKU 50 并发扣减，无死锁导致的 500；失败请求得到"请重试"或 429，而非系统错误。
- 验收: 发生重试时可从日志定位（订单号、重试次数、原始错误码）。
- 约束: 重试次数与单请求总时长有硬上限；业务错误（库存不足）不重试。（关联 ADR-003）

### T-006 审计改为事务内 outbox + 轮询投递

- 验收: 下单成功后立即 kill -9 进程，重启 5 分钟内该订单的审计记录一定存在。
- 验收: 能按 orderNo 判定审计"是否缺失"（现状无法判定）。
- 约束: 副作用与订单主事务同生共死；重复投递不产生重复审计；不引入 MQ。（关联 ADR-002）

### F-001 退款：运营可发起全额/部分退款，状态可追踪

- 验收: 运营对已支付订单发起全额或部分退款，5 分钟内可在系统内看到状态与失败原因。
- 验收: 退款成功后库存按规则回补，且只回补一次。
- 约束: 退款单是唯一事实源，订单状态由退款结果驱动；部分退款累计不得超过订单金额。
- 边界: 本期不做审批流、不做多级审核、不做非原路退回。（关联 ADR-006；渠道能力见 VISION 待确认 #1）

### F-005 运营侧查询与退款入口最小鉴权

- 验收: 无凭据访问查询/退款接口返回 401/403，且不返回任何订单数据。
- 验收: 凭据轮换可通过改配置 + 重启完成，步骤写进发布手册。
- 约束: 不自建账号体系；用户侧下单接口不受影响。（关联 ADR-010）

### F-003 订单查询：按订单号/手机号/时间段分页

- 验收: 可按订单号、手机号、下单时间段组合查询，分页返回，单页 ≤ 100 条。
- 验收: 查 90 天数据 P95 < 1s，且下单接口延迟不受影响（同库场景需给出取舍说明）。
- 约束: 只读，不提供任何修改能力；手机号脱敏展示。（关联 T-005、T-010、ADR-007）

### F-002 退款失败自动补偿与人工重试入口

- 验收: 渠道超时/失败的退款在补偿周期内自动重试；超过阈值转"待人工处理"并出现在待办列表。
- 约束: 重试不得造成重复退款。（关联 ADR-006、F-001）
