# 02 · 等价类划分 + 边界值分析

> 最高频方法，覆盖 ~80% 纯输入→输出场景。等价类把无限输入压成有限代表，边界值钉住 off-by-one 高发区。

## 等价类划分

### 有效 vs 无效

- **有效等价类**：符合规格/契约的输入，程序应正常处理。→ 对应"正向"。
- **无效等价类**：违反规格/契约的输入，程序应拒绝（抛异常/错误码/空）。→ 对应"反向/异常"。**无效类往往比有效类还多**（`[1,100]` 有 1 个有效类，却有 `<1`/`>100`/`null`/非数字等多个无效类）。

### 划分四步

1. **从规格提取约束**：读注释/接口契约/业务规则，找出每个输入的取值范围、类型、格式约束。
2. **划分有效等价类**：按"会走不同处理分支"切分（按行为差异，非数值大小）。
3. **补全无效等价类**：每个约束的违反都是一类（越界、空、null、类型错、格式错）。
4. **每类取一个代表 + 边界值覆盖**。

> 按行为切不按数值切：✗ `[1,100]` 切成 `[1,50]`/`[51,100]`（两段行为可能一样，白费用例）✓ `[1,100]` 一个有效类 + `<1`/`>100` 两个无效类。

## 边界值分析

闭区间 `[min, max]` 必测 4 个边界值：`min-1`（无效）、`min`（有效）、`max`（有效）、`max+1`（无效）。

### 不同输入类型的边界

| 输入类型 | 边界值 |
|---|---|
| 数值区间 `[min,max]` | `min-1, min, max, max+1` |
| 有序集合/列表（长度 n） | `0`（空）、`1`（单元素）、`n`（满）、`n+1`（越界） |
| 字符串 | `""`（空串）、`null`、`1` 字符、`maxLength`、`maxLength+1`、纯空白 `"   "` |
| 日期 | 区间两端 + 跨天/跨月/跨年/闰年 2-29 + 时区切换点 |
| 索引/分页 | `0`、`1`、`size-1`、`size`（越界）、负数 |

### 高风险域的边界优先级（Pareto）

以下域的边界是 off-by-one 与精度 bug 的重灾区，**优先覆盖**（与 `java-coding-guide-pro` 的 S 级高风险域呼应）：

- **金额**：`0`、负数、极小数（`0.005` 四舍五入）、极大值（溢出）、小数位超出 scale。
- **日期时间**：`00:00:00` 与 `23:59:59`、月末、闰年 `2024-02-29`、跨时区日切、`now()` 的 mock。
- **索引/分页**：`page=0`/`page=1`（0 基还是 1 基常混）、超出总数的页、负数页。
- **集合容量**：空集合、恰好容量、超容量扩容点。

## 完整示例：最小充分集设计

**被测方法**（典型业务校验）：

```java
/**
 * 计算订单折扣价。
 * @param originalPrice 原价，必须 > 0，单位分（int，避免浮点）
 * @param discountRate  折扣率，范围 (0, 1]，例如 0.8 = 8 折
 * @return 折后价（分），向上取整到分
 * @throws IllegalArgumentException originalPrice <= 0 或 discountRate 越界
 */
int calculateDiscountPrice(int originalPrice, double discountRate)
```

### 步骤 1：划分等价类

**originalPrice**（`> 0` 的 int）：
| 等价类 | 有效/无效 | 代表值 |
|---|---|---|
| `price <= 0` | 无效 | `-1`, `0` |
| `price > 0`（正常） | 有效 | `10000` |

**discountRate**（`(0, 1]`）：
| 等价类 | 有效/无效 | 代表值 |
|---|---|---|
| `rate <= 0` | 无效 | `-0.1`, `0` |
| `0 < rate < 1`（打折） | 有效 | `0.8` |
| `rate == 1`（不打折，边界） | 有效 | `1.0` |
| `rate > 1` | 无效 | `1.1` |

### 步骤 2：补边界值

- originalPrice 边界：`0`（无效端点）、`1`（有效最小）、`Integer.MAX_VALUE`（极大，防溢出）
- discountRate 边界：`0`（无效）、`1.0`（有效上界）、略大于 0 如 `0.001`、略大于 1 如 `1.0 + epsilon`

### 步骤 3：四维度合并 → 最小充分用例集

> 注意：两个输入的**无效等价类通常单独测**（一次只让一个输入非法，定位清晰），有效类才组合。

| # | 维度 | originalPrice | discountRate | 期望 | 设计依据 |
|---|---|---|---|---|---|
| 1 | 正向 | `10000` | `0.8` | `8000` | 有效+有效，典型折扣 |
| 2 | 边界 | `10000` | `1.0` | `10000` | 折扣率上界（不打折） |
| 3 | 边界 | `1` | `0.8` | `1` | 原价最小有效值 |
| 4 | 边界 | `10000` | `0.001` | `10`（向上取整） | 折扣率下界附近 + 取整 |
| 5 | 反向 | `0` | `0.8` | throw | price 无效类 |
| 6 | 反向 | `-1` | `0.8` | throw | price 无效类（负数） |
| 7 | 反向 | `10000` | `0` | throw | rate 无效类下界 |
| 8 | 反向 | `10000` | `1.1` | throw | rate 无效类上界 |
| 9 | 边界 | `Integer.MAX_VALUE` | `0.5` | 校验不溢出 | 极大值（防 int 溢出 bug） |

**9 个用例覆盖了**：2 个有效等价类的代表、所有边界端点、全部 4 个无效等价类、取整行为、溢出风险。这远比"想到几个写几个"系统——且没有冗余（同类内不重复取值）。

### 步骤 4：落地为代码

有效类多正常用例（#1-#4）→ `@ParameterizedTest` + `@CsvSource` 把用例当数据；反向用例（#5-#8）→ 各自 `assertThrows`。完整写法见 `references/06-tools-lean.md` §2 映射表。

## 用例计数经验

- 纯计算/校验方法：**3~8 个有效/边界用例 + 每个无效等价类 1 个反向用例**，通常共 5~10 个。边界值让总数 +2~4 个。
- 同一等价类内取一个代表即可，省下的额度测别的等价类（详见 antipatterns）。

> "写多少"的更系统判断见 `references/05-coverage-and-quantity.md`：用覆盖率反向校验、用变更频率（热路径）加码。

## antipatterns

- **✗ 只测有效等价类**（"传正常值返回正常"） → ✓ 补全每个无效等价类，反向用例是发现 bug 的主力。
- **✗ 同一等价类取多个代表**（如测 `1,2,3,4,5` 都在 `[1,100]` 内） → ✓ 一类一代表，省额度测边界和无效类。
- **✗ 忘记边界，只取类内典型值**（如 `[1,100]` 只测 `50`） → ✓ 必测 `min, max, min-1, max+1`。
- **✗ `null` 从不测**（"调用方不会传 null"） → ✓ `null` 是独立无效等价类，`@Nullable` 参数必测。
- **✗ 两个非法输入同时传入**（`price=-1, rate=1.1` 一起测） → ✓ 一次只让一个输入非法，否则失败时不知哪个条件触发。
- **✗ 浮点用 `==` 断言** → ✓ 用 `assertEquals(expected, actual, delta)` 或改用整数（本例用"分"为单位避免浮点，呼应 guide-pro 金额规约）。
