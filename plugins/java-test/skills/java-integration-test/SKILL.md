# Java 集成测试（真实依赖 / 冒烟 / E2E）

本技能管**测试自己拉起并管理真实依赖**的那一层：真实数据库与中间件、迁移可重放、事务传播的实际效果、冒烟、API 级 E2E、外部调用隔离。与开发期测试的分界沿**依赖轴**——开发期零外部基础设施（→ java-unit-test），本层自己起依赖，CI 无预置环境也能重复跑。

**Testcontainers 是首选执行方式，不是本层定义。** 它属回归阶段，开发阶段要的是毫秒级反馈。没有 Docker 时本层仍有合法路径，见决策 ③。

> 判据与陷阱围绕 **Spring 的测试上下文**（`@SpringBootTest` / 切片注解 / `@MockitoBean` / Testcontainers）。换 Micronaut / Quarkus / 纯 JUnit 自建容器，三个决策照旧成立，下面的陷阱表基本归零——它们不是「测试」的通用坑，是 Spring 测试容器特有的欺骗方式。

## 三个决策，按序走完

顺序不能换：先判该不该建，再判放哪层，最后才判用什么跑。跳过 ① 直接问"怎么起容器"，等于假定这一层一定要有。

### ① 建不建 —— 这段代码的回归由谁值守

| 值守情况 | 动作 |
|---|---|
| 有专职测试 / QA | 不自建，开发只保证单测绿；用户明示要才写 |
| 无专职测试（个人 / 小团队） | 建，但优先**冒烟 + 核心链路**，不铺分支矩阵 |
| 判断不了 | 先问"这个模块的回归谁跑"，再决定 |

不自建不是偷懒——专职同学的用例会长期维护，你写的那份下次需求变更就烂在那。

> ① 只决定**集成层**建不建。契约切片（`@WebMvcTest` / `@JsonTest` / `@RestClientTest`）秒级、不碰真实依赖，不受 ① 排除——有专职测试也照写。

**激活时机**（与上表叠加）：

| 信号 | 动作 |
|---|---|
| **明示**：用户说"补集成测试 / 需求冻结 / 准备发版 / 要 Testcontainers" | 直接开始，不追问 |
| **推断**：特性已稳 + SQL 密集 + 覆盖为零，用户没说 | 先问一句，确认后动手 |
| **无信号**：开发期常规写码 / 新功能开发 | 不新增；新测试 → java-unit-test；存量照跑照修 |

> 这一层是十秒级/条的重资产，写在还变动的行为上 = 需求每变一次连带重写。默认永远从轻，重的东西等人开口。

### ② 放哪层 —— 这条断言离开真实依赖还成立吗

- 成立 → 集成层：SQL 方言特性（`jsonb` / `ARRAY` / `ENUM`）、迁移脚本、事务传播实际效果、缓存过期与序列化语义、消息协议。
- 不成立 → 不进集成层：业务规则、多条件分支矩阵、DTO 映射、参数校验、权限逻辑、JSON 编解码、HTTP 客户端逻辑。

| 测什么 | 层 | 工具 |
|---|---|---|
| Service 分支矩阵（mock Repository） | 纯单测 | → java-unit-test |
| Controller 参数校验 / 路由 / 异常处理 / JSON | 契约切片 | `@WebMvcTest` / `@JsonTest` / `@RestClientTest` |
| SQL 实际执行 / 迁移 / 事务传播 | 集成层 | `@SpringBootTest` 或 `@DataJpaTest` + 真实库 |
| 完整 HTTP 管道（过滤器 / 拦截器 / 序列化） | 集成层 | `@SpringBootTest(RANDOM_PORT)` |
| 服务起得来 + 核心链路通（冒烟 / 多接口串联） | 集成层 | `@SpringBootTest` + Actuator health、`RANDOM_PORT` 多步 |
| 外部 HTTP 依赖隔离 | — | WireMock stub，不真调 |

集成用例每特性 1~3 条锚定真实行为；分支矩阵铺纯单测，不铺集成层。无专职测试时冒烟优先于逐特性用例——部署炸比逻辑错更致命。

**curl 结果不是测试**：必须有结构化断言（status + body 字段），"看起来返回正常"不算。手动启动应用再肉眼判断同样不算。

### ③ 用什么跑 —— 环境起得起容器

| 环境 | 路径 | 代价 |
|---|---|---|
| 有 Docker（本机或 CI） | Testcontainers，镜像 tag 对齐生产 | 单条十秒级，首次拉镜像慢 |
| 无 Docker，本机能起真实库 | 连本地实库 + 每个测试类独立 schema | **不可重复**：换机器 / 上 CI 就挂，库版本可能与生产不一致 |
| 都没有 | 能验的用同族嵌入式替身验，不能验的列清单移交真库 | 有盲区，必须逐条写明 |

**同族嵌入式替身**指同一类依赖的内存版：关系库用 H2（`MODE` 对齐目标库）、缓存用嵌入式 Redis、消息用内嵌 broker。没有同族替身的组件（如特定 NoSQL）就不验，直接进移交清单。

第三条怎么切，看**这条断言依赖什么**：

| 断言依赖什么 | 替身能验吗 | 例子 |
|---|---|---|
| 事务传播与回滚的最终状态 | 能 | 写订单失败后库存是否恢复 |
| 唯一约束是否真的拦住 | 能 | 重复订单号插入被拒 |
| SQL 方言特性 | 不能 | `jsonb` / `ARRAY` / `ON CONFLICT` / 排序与大小写敏感性 |
| 具体错误码与异常类型 | 不能 | 驱动异常层次与错误码两边不同 |

**选了哪条必须写进回复**（例："走第二条，依赖本机 MySQL，不可重复"）。用替身时同样要标注：「非生产方言，以下行为未验」并列出移交清单。

**空手说"不写"和"拿替身冒充真库"一样不合格**——前者放弃了本来能自动兜住的回滚与约束。事务提交/回滚的最终状态是 JDBC/Spring 语义，与方言无关，替身上验是有效的；只有方言特征必须等真库。

## 假绿的三条生成机制

具体测试代码模型会写，会错的是**判断什么时候绿灯是假的**。九条陷阱都能由三条机制推出来；命中时读 `references/01-pitfalls.md`，那里有推理过程和怎么验证自己不是假绿。

### 一、测的不是生产那条路径

**识别问题：这条断言走过的每一环，生产上也会走吗？**

| 断在哪 | 表现 |
|---|---|
| 测试级 `@Transactional` 验回滚 | Service 的 `REQUIRED` 事务并入测试事务，异常只标 rollback-only，回滚断言恒真 |
| `RestAssuredMockMvc` 当真实 HTTP | 走进程内 MockMvc，过滤器 / 序列化 / 线程模型全绕过 |
| `@DataJpaTest` / `@JdbcTest` 默认 `replace = ANY` | 真实 `DataSource` 被静默换成内嵌库，方言行为测不到 |
| `any()` 放过参数构造 | 被测代码构造的 wrapper 字段写错也不报 |
| 外部 API 真调（支付 / 短信 / 三方认证） | 测的是对方可用性，产生费用，结果不可重复 |

### 二、验的时间点不对

**识别问题：断言执行那一刻，这个值已经定了吗？**

| 表现 |
|---|
| `RANDOM_PORT` 下配 `@Transactional`——请求走容器线程，测试事务管不到它，脏数据留在库里。这不叫假绿，是隔离完全失效 |
| 异步 / 消息驱动，没等消费完成就查库 |
| 断言落在清理动作之后 |

### 三、失败没被算成失败

**识别问题：如果这行代码坏了，哪条断言会红？答不出来就是没有断言。**

| 表现 |
|---|
| 启动日志里有 WARN / ERROR（Bean 条件装配被跳过、迁移部分失败、连接池降级），测试照绿 |
| 异常断言断在 `RuntimeException` / `Exception` 根父类，抛 NPE 也算通过 |
| 没有断言，调一下方法不抛异常就算覆盖 |
| 桩返回恒等于期望值，任何实现都能过 |

### 附带：不假绿但会让套件被放弃

不会骗你，但会让这层测试跑到没人愿意跑。**测得太慢的套件等于没有套件。**

| 表现 | 判据 |
|---|---|
| 容器不是 `static` | 每个测试方法启停一次，单条十秒级 |
| 起了用不到的容器 | 把这个 `@Container` 注掉，测试还绿吗？绿说明它没验证任何东西 |
| Context 缓存失效 | `@MockitoBean` 组合频繁变化 / 每类都加 `@DirtiesContext`，整个上下文反复重建 |
| 连接数打满 | 表现为随机卡住而非变慢。上限是「并行类数 × 池大小」，不是单个类的池大小 |
| `withReuse(true)` 跨类复用 | 上一轮脏数据还在，单跑绿、全量红 |

## 数据隔离三选一

| 手段 | 适用 | 代价 |
|---|---|---|
| 测试方法 `@Transactional` 回滚 | 只有 `MOCK` 模式的 `@SpringBootTest` 与切片测试 | `RANDOM_PORT` 下失效（见机制二） |
| `@Sql` / 精确 `DELETE` 清理 | 任何模式 | 要写清理语句，漏表就残留 |
| 每个测试类独立库名 / 独立容器 | 需要并行、需要真提交的用例 | 上下文或容器多一份，启动更慢 |

## 交付前自检

- [ ] 已过决策 ①（值守 + 时机）；没通过时没有新增集成用例
- [ ] 回复里写明了决策 ③ 走的是哪条路径；用替身时标了盲区并列出移交真库的清单
- [ ] 每条用例过准入判据，每特性 ≤3 条，分支矩阵不在这一层
- [ ] 类名 `*IT` 且真的会被执行：Maven 用 failsafe 绑 `verify`，Gradle 用独立 `integrationTest` sourceSet 绑 `check`，都没混进 `mvn test` / `test` task
- [ ] 每个测试有结构化断言（status + 响应体字段），没有 curl / 肉眼判断
- [ ] 每条断言能答出"如果这行代码坏了，哪条会红"
- [ ] 验证回滚的用例**没有**用测试级 `@Transactional`；`RANDOM_PORT` 场景已改为显式清理
- [ ] 启动日志里的 WARN / ERROR 已排查
- [ ] 外部依赖走 WireMock，没有真调

## 版本与范围

- Spring Boot 2.7 / 3.x / 4.x 均适用。Boot 4 的测试工具链有破坏性变化（`TestRestTemplate` 废弃、`@MockBean` 移除、Testcontainers 模块改名），这些都是**编译错误**，升级时会立刻暴露，按编译提示改即可。
- 镜像 tag 一律对齐生产版本，不硬编码某个 patch 号——具体数值写在项目配置里，不在技能里。
- **注解分界**：无 Context 的 `@Mock`、只装 mock 的 `@TestConfiguration` → java-unit-test；`@SpringBootTest` / `@MockitoBean` / 切片注解 → 本技能。过了决策 ① 才动手。
- **不适用**：前端 E2E（Selenium / Playwright / Cypress）、性能测试、安全测试。
