# 03 · Antipatterns（硬价值）

init 类技能最常见的错误。每条含「✗ 错误做法 → ✓ 正确做法 → 为什么」。
生成 AGENTS.md 前必看——核心价值在"防致命错"。

---

### 1. 为多个工具各建一份实质内容记忆
- ✗ 同时生成 `AGENTS.md` + `CLAUDE.md` + `.cursorrules` + `.windsurfrules`，每份都写一遍项目事实。
- ✓ 只产一份承载内容的 `AGENTS.md`；工具专属文件最多留**零内容适配指针**（如 `CLAUDE.md` 仅一行 `@AGENTS.md`，见 `05`）。
- 为什么：多份实质内容必然漂移（改了一处忘改另一处）；适配指针是单点引用，不产生第二份事实。

### 2. 在 AGENTS.md 里写工具专属 hack
- ✗ 在 **AGENTS.md 正文**写"用 `@` 引用文件""把规则放 `.cursor/rules`""Claude 请读 `CLAUDE.md`"。
- ✓ AGENTS.md 只描述项目事实（命令/约定/架构/硬约束/陷阱）；工具专属语法只允许出现在**适配指针文件**里（如 `CLAUDE.md` 的 `@AGENTS.md` 引用行，见 `05`）。
- 为什么：AGENTS.md 的护城河是"工具无关、跨工具通用"。混进工具 hack 会破坏通用性；适配指针的作用恰是充当工具的挂载点，二者分工不同。

### 3. 把 AGENTS.md 当 changelog / wiki / 进度日志
- ✗ 写版本发布记录、团队成员介绍、Roadmap；或写"- [ ] 待实现：XX"、"当前进度：已完成 3/5"、"本周 TODO"。
- ✓ 只写"每个请求都该加载"的高密度上下文与稳定约定；历史/百科放 README/wiki，待办/未决/进度留在 issue / 看板 / 会话上下文。
- 为什么：changelog/wiki 会撑爆行数稀释信号（≤200 行是推荐上限，Claude Code 实践参考）；进度类内容会让 AGENTS.md 变成高频过期状态日志——AI 每次加载都读到过期的"当前状态"。它是给"新同事"的背景说明，不是给"项目经理"的进度周报。

### 4. 生成后不 review 直接 commit
- ✗ 写完 `AGENTS.md` 立刻 `git add` + `commit`。
- ✓ 给出草稿 → 用户 review → 用户决定 commit。
- 为什么：自动提交可能把"需核实"的臆造命令、或误读的信号固化进仓库，污染后续所有 AI 会话。

### 5. 把 CLAUDE.md 当第二份记忆并存
- ✗ 已有 `CLAUDE.md`，仍另起一份 `AGENTS.md` 重复写一遍；或迁移后把 CLAUDE.md 原文删掉。
- ✓ 读取 `CLAUDE.md` 全文（含展开其 `@import` 链），内容并入 `AGENTS.md`，然后把 `CLAUDE.md` **降为零内容适配指针**（一行 `@AGENTS.md` + 可选 Claude 专属小节），文件本身保留（见 `05`）。
- 为什么：Claude Code 只读 CLAUDE.md 不读 AGENTS.md，直接删文件会让它丢失项目上下文；保留 stub 是兼容而非并存，仍是单一事实源。

### 6. 把 AI 能自己读的内容塞进去（API 文档 / 文件树）
- ✗ 把每个模块的函数签名、参数表全抄进 AGENTS.md；或罗列 `src/ / components/ / utils/ ...` 目录结构。
- ✓ 只写架构、约定、硬约束、陷阱；API 细节与文件树让 AI 直接读代码。
- 为什么：AI 能自行 `Glob`/`Read` 源码；塞这些既撑爆行数又很快过时。AGENTS.md 该补的是"为什么这么分""模块间如何协作"这类 AI 看不出的人脑上下文。

### 7. 写"理想规则"——团队实际不遵守的规范
- ✗ 写"所有函数必须有 JSDoc""禁止 any""提交必须 review"但团队从不执行。
- ✓ 只写 CI 强制项与团队真实遵守的约定。
- 为什么：理想规则会误导 AI 按不存在的标准改代码，引发无谓改动与冲突。

### 8. AGENTS.md 写得太空 / 必知红线漏写
- ✗ 只写 3-5 行概述（"这是 X 项目，用 Python"）就完事；或把关键红线（改动即破坏的约束）写进叙述里而非独立成行。
- ✓ 每条"改动会出错/违规"的约束必须进 **Hard constraints 独立成行**（如"禁止改 summarize 函数签名，测试依赖它"）；项目特定红线宁可多写一行，不可省略。
- 为什么：AGENTS.md 太短时 AI 缺关键上下文，会按通用假设改代码；红线不独立成行时防护强度依赖读者推断，实测中被弱化（曾见签名约束写进 Architecture 的"稳定接口"后防护失效）。

### 9. monorepo 不嵌套子 AGENTS.md
- ✗ 大 monorepo 只在根放一份，子包特殊约定全堆根文件。
- ✓ 子包就近放 `AGENTS.md` 覆盖本目录，根文件管全局（见 `04`）。
- 为什么：根文件膨胀且子包上下文被稀释；嵌套是 AGENTS.md 规范明确支持的层级扩展，仍属同一套通用记忆。

### 10. 命令臆造不经核实
- ✗ 没看 `package.json`，凭印象写 `npm run dev`（实际是 `pnpm dev`）或 `npm test`（实际无该 script）。
- ✓ 命令从构建文件实际提取；无法确认标「需核实」并询问。
- 为什么：误写构建命令比不写更糟——AI 会反复执行失败命令，浪费轮次且误导。

### 11. 把敏感信息写进去
- ✗ 写真实 token、密码、内网地址、PII。
- ✓ 只写约定（"用 `.env`""有 `.env.example`"），绝不写明文密钥。
- 为什么：AGENTS.md 通常入库且被多工具读取，泄露即安全风险。

### 12. 更新姿势错误：不维护或整份覆盖
- ✗ 生成一次后依赖/结构/CI 大变仍用旧文件、命令失效也不更新；或更新时生成一份全新内容整份覆盖，丢弃用户手写的有效约定与项目特有背景。
- ✓ 把"更新优化"作为一等能力（Path B）：重扫变更面信号，逐 section 比对标注「过期/缺失/仍准确」，只改需要改的、保留用户原有有效内容，给出 diff 式修订建议 + 修订后完整草稿（C1 流程）。
- 为什么：过期的 AGENTS.md 比没有更危险——持续向 AI 提供错误信号；而用户手写内容往往含 AI 扫不出的"人脑上下文"（政治/合规约束、历史坑），整份覆盖会丢失这些信息且易引发抵触。增量 diff 才是"更新优化"而非"推倒重来"。

### 13. 无界扫描 / 全文 Read 导致 Token 爆炸
- ✗ 用 `Glob("**/*")` 或全目录 `Grep` 递归 `node_modules` / `dist`；为"看一眼结构"全量 `Read` 长文件；更新阶段对未变更文件重复全量重扫。
- ✓ 遵守 `01` §0 **Token 经济学 7 铁律**（限定范围/元数据优先/懒加载/Bash 聚合/签名提取/Git 增量/先聚后出）。
- 为什么：无界扫描几分钟内撑爆上下文、造成 Context Rot 与高额 Token 成本，让 Agent 在噪音中迷失真信号。
