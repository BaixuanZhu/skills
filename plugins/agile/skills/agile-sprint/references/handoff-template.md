# 交接文档模板（agile-sprint 参考）

交接产物正文模板。单执行者路径用于 Sprint「交接契约」声明的跨仓交接点；工作包模式复用正文承载具体依赖产物，同仓多接收方也可使用，不另强制生成第二份交接文档。

工作包的来源、版本身份、依赖与验收字段只按 `using-agile/references/sprint-schema.yaml` 的 `work_delivery`；流程见 `using-agile/references/workflow.md §三（工作包交付）`。上游在独立回执中提供来源和实际正文，中枢验收后由 export 交付下游，不能只给一个接收方不可访问的路径。

## 一、文件命名与位置（仅单执行者路径）

工作包模式不套此命名，正文进入版本化产物；来源与实际内容采集一次。以下位置仅供原跨仓交接文档使用：

    sprints/handoffs/sprint-{序号:03d}-H{交接点序号:02d}.md

- 位置固定 `sprints/handoffs/`（随 Sprint 归档，不随某个具体仓库提交）
- 命名对应 Sprint 文件「交接契约」表中的交接点（H-001 → H01）
- 交接点序号从 01 起，跨 Sprint 不续号（每个 Sprint 独立编号）

## 二、模板

工作包取本模板相关正文小节，版本与来源由协议字段承载，不重复抄元数据；单执行者交接文档使用完整模板。

```markdown
# 交接: {交接点} {上游任务标题} → {下游任务标题}

- Sprint: sprint-{序号:03d}-{日期}
- 上游任务: {id}（repo: {仓库名}）
- 下游任务: {id}（repo: {仓库名}）
- 产出日期: {YYYY-MM-DD}

## 接口/数据契约

{上游交付给下游的接口或数据结构——按需选择并填写，未涉及的小节删除}

- 接口清单：{方法 + 路径 + 一句话用途}
- 请求/响应示例：{含字段说明与错误码}
- 数据模型：{表/对象结构、字段变更、兼容性说明}

## 配置与环境变更

- 新增/变更的配置项：{配置名、用途与生效范围；凭证只写取得方式，不填真实值}
- 环境变量 / 依赖服务：{下游启动前需具备的前提}

## 运行与验证方式

- 上游启动步骤：{命令/顺序}
- 冒烟用例：{下游可自行验证的最小调用序列 + 期望结果}

## 未决事项与联调注意点

- {未定接口/行为歧义/后续变更预告；无则写"无"}
- {联调时的已知坑或前提假设}
```

## 三、填写规则

- **契约优先**：接口路径、字段、错误码、数据模型必须与上游真实实现一致，**禁止凭规划时的设想脑补契约细节**；不确定的字段标 `{待定}` 并列入「未决事项」
- **按需裁剪**：模板小节仅保留本次交接涉及的部分，无关小节删除（如纯数据模型交接可无"配置与环境变更"）
- **完成标准**：单执行者上游任务完成须含交接文档（未产出 → DoD 时归入 moved_next）；工作包产物须经回执验收才可给下游，包验收不等于业务条目整体完成
- **变更同步**：单执行者交接文档由消费 Agent 在联调期就地更新；工作包不得改已导出快照或已验收正文。重规划按 `work_delivery` 提升同 Sprint revision，使全部旧包回执失效并保留历史；已有条目整体完成则不能重规划，新工作进新 Sprint
