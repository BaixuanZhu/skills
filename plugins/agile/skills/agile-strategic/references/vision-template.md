# 产品愿景模板（agile-strategic 阶段 A 参考）

> 本模板 = **通用愿景硬结构** + **当前愿景独有部分**（核心用户、成功指标）。
> 写 VISION.md 时，把 `{占位}` 替换为决策问询确认后的真实内容。**`{待确认}` 仅限用户明确说"跳过"的项**（`using-agile/references/probing-protocol.md §二` 规则 3），不得用于绕过问询；所有 `{待确认}` 项必须同步登记到文末"待确认项汇总"。关键决策（定位/核心原则/红线/指标）每条标来源：`（来源：用户给出 / agent 推断 / agent 推荐待确认）`。

```markdown
# 产品愿景文档 — {项目名}

> 基线来源：{决策依据文档 / 对话}

## 电梯演讲（Elevator Pitch）
> 对于**{目标用户}**而言，{项目名} 是一个 {品类/定位}，它提供 {核心价值}，而**不 {明确不做的事}**。不同于 {对标反面}，{项目名} 以 {对标对象} 为结构级对标，{差异化一句}。
> （来源：{用户给出 / agent 推断}）

## 核心用户（Core Users）
- **主要**：{画像 + 使用场景}（来源：{…}）
- **次要**：{画像 + 使用场景}（来源：{…}）

## 定位声明（状态：{终稿 · 不可逆 / 探索中}）
- {定位句1}（来源：{…}）
- {定位句2}（来源：{…}）

## 使命（Mission）
{一句话使命}

## 愿景（Vision）
{一句话愿景}

## 核心原则（优先级排序的底层逻辑）
1. **{A} 优先于 {B}** — {解释}（来源：{…}）
2. **{C} 优先于 {D}** — {解释}（来源：{…}）

## 战略红线（永远不做）
| 类别 | 红线 | 来源 |
|------|------|------|
| 平台角色 | {不自营/不控货/不履约…} | {…} |
| 用户结构 | {不面向泛 C 端/不追求规模…} | {…} |
| 产品功能 | {不做娱乐化/社交化…} | {…} |
| 商业化 | {不卖无关广告/不以流量为核心…} | {…} |

## 只做清单（极简执行版）
1. 只做 {…}（来源：{…}）
2. 只做 {…}（来源：{…}）

## 成功指标（可量化 KPI）
- {指标1}：{目标值}（{时间窗，如发布 30 天内}）（来源：{用户给出 / agent 推荐}）
- {指标2}：{目标值}（{时间窗}）（来源：{…}）
- 例：注册开发者 ≥ 500、周活 ≥ 150、全文搜索 P95 < 200ms

## 愿景对齐检查（创建任何故事前的必问）
> **这个故事是否服务于「{愿景核心价值一句}」？**
> 不能明确回答「是」的事项，不进入 Backlog。

## ⚠️ 战略冲突待裁决（如有）
{若有与基线矛盾的需求/文档，链接 `STRATEGY_CONFLICT.md` 并说明待用户裁决的内容}

## 待确认项汇总（如有）
| # | 待确认项 | 所在章节 | 跳过原因 |
|---|----------|----------|----------|
| 1 | {项} | {章节} | 用户明确跳过（{日期}） |
```
