# 08 · 边界语义

需求文档几乎不会写这些，但它们决定调用方能不能安全地用你的方法。同一个方法，这三种取舍都会静默生效、都不会报错，最后数据按不同规则落库。

## 一、无结果返回什么

| 场景 | 返回 | 禁止 |
|---|---|---|
| 查询单条，可能不存在 | `Optional<T>` | 返回 `null` |
| 查询列表 | 空集合 `List.of()` / `Map.of()` | 返回 `null` |
| 聚合（求和、平均、最大） | `Optional`，或抛异常（见下） | 返回 `0`（`0` 与「无数据」语义不同） |
| 布尔判断 | `false` | — |

聚合值返回 `0` 是常见误判：`avgAmount` 对空集合返回 `0.00`，与「平均金额确实是 0」不可区分，报表上会变成一条假数据。要么 `Optional` 让调用方决定，要么抛 `IllegalArgumentException` 要求调用方先判空。

「不返回 `null`」也管字段：DTO / VO 里的集合字段初始化成 `List.of()`，别留 `null` 等前端崩。

## 二、null 参数

| 参数性质 | 处理 |
|---|---|
| 必填（缺它无意义） | `Objects.requireNonNull(x, "x")`，fail fast |
| 可选（`null` 有业务含义） | 显式处理，javadoc 写清 `null` 表示什么 |
| 集合参数 | 按空集合处理，`null` 与空等价 |

**不给必填参数编默认值。** `hasAmountOver(orders, threshold)` 把 `threshold == null` 当作 `BigDecimal.ZERO` 后，方法等价于「是否存在金额大于 0 的订单」，几乎恒为 `true`。这类容错把「调用方传错」变成「结果永远为真」，比抛 NPE 难查得多。

判据：**参数 `null` 时是否有一个唯一正确的结果？** 有 → 容错并写进 javadoc；没有 → `requireNonNull`。

## 三、集合里的 null 元素

默认跳过，不参与计算，也不让整批失败。入参常来自外部（DB 查询、反序列化、第三方回调），容忍脏元素比让调用方先清洗更符合业务预期。

若业务要求「有 null 就拒绝」，在方法开头显式校验并抛异常，写明校验意图——不要靠循环里的 `continue` 静默跳过再声称已校验。

## 四、重复 key

| 构造方式 | 重复时 | 何时用 |
|---|---|---|
| `putIfAbsent` | 保留首条 | **默认**：幂等导入、去重 |
| `put` | 后者覆盖 | 需要最新值（如按时间升序排过再覆盖），须注释说明 |
| `toMap` 两参 | 抛 `IllegalStateException` | 只有确定唯一时才用 |
| `toMap` 三参 `(a, b) -> a` | 保留首条 | 与 `putIfAbsent` 等价 |
| `toMap` 三参 `(a, b) -> b` | 保留末条 | 同上，需注释 |
| `groupingBy` | 天然聚合 | 同 key 需要合并而非择优时 |

`put` 与 `putIfAbsent` 的差别在重复数据上完全静默：同一份导入逻辑，写 `put` 的保留最后一条，写 `putIfAbsent` 的保留第一条，两种都不报错，数据已经按不同规则落库。

## 五、非法参数

| 场景 | 默认 | 理由 |
|---|---|---|
| 分页 `pageNo < 1` | 纠正为 1 | 展示层容错，前端偶尔传 0 |
| 分页 `pageSize < 1` | 返回空列表 | 0 页无意义 |
| 分页越界 | 返回空列表，不抛异常 | 翻到末页之后是正常操作 |
| `topN` / `limit` 为负 | 返回空集合 | 同上 |
| 状态码 / 枚举值不认识 | 抛异常 | 领域层不猜 |

判据：**展示层容错，领域层 fail fast。** 分页、排序、每页条数是展示层；订单状态、支付渠道、业务类型是领域层——后者遇到不认识的取值，静默映射成默认值等于把数据错误当正常处理。

## 六、静态还是实例

| 类型 | 选择 |
|---|---|
| 只依赖入参的纯函数 | `static` |
| 依赖注入的协作者（Repository、`Clock`、配置） | 实例方法 + 构造器注入 |
| 工具类 | `static` + `final` 类 + 私有构造器 |

同一个类内不混用：要么全 `static`，要么全实例。混用时调用方写法不同，合并代码那一步才会暴露。
