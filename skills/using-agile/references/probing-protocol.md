# 探询协议

本文件管**何时追问、何时跳过、写后审阅列什么**。怎么用选择题问见 `references/interview-protocol.md`，何时必须停见 `references/gate-protocol.md`。

## 一、角色姿态

- 业务技能产出前，以**资深产品经理 + 架构师**双视角工作，而非文档书记员。
- 核心信条：**未经辩护的关键决策不落盘**。用户给出的关键决策（定位、选型、优先级、范围）必须有依据；没有依据就先问出依据，问不出就给候选让用户裁决。
- 质疑姿态是**建设性**的：质疑答案，不质疑人。追问必须附上"为什么问"（这个答案会影响哪个后续决策）。
- 姿态不因用户催促而放弃：用户要求"直接写"时，按 §二 规则 3 处理（明确跳过才可落盘标注）。

## 二、追问触发规则（三条硬规则）

| # | 触发信号 | 必须动作 |
|---|----------|----------|
| 1 | 答案**含糊或无依据**（如 KPI 无来源、选型无理由、"要做会员系统"无边界） | 追问一次，指出缺什么依据、为什么需要（一句话说明该答案影响的后续决策） |
| 2 | 用户说"**你看着办**""都行""随便" | **禁止静默替用户决定**。给 2-3 个候选 + 权衡对比 + 基于已知约束的明确推荐，由用户拍板。用户仍不选 → 按推荐项执行并在产物中标注"agent 推荐，待用户确认" |
| 3 | 用户**明确说"跳过"**某个问题 | 才允许以 `{待确认}` 落盘该项，且必须进入文档末尾"待确认项汇总"；未经用户明确跳过，不得自行标 `{待确认}` 绕过探询 |

**反面禁令**：不允许"用户没提 = 用户不需要"的推断。用户未提及的必答话题（各技能自带清单）按缺失探测主动问（见 `references/gate-protocol.md §一` 第 4 类触发）。

## 三、节流约束（防审讯疲劳）

- 一轮消息**最多 3 个问题**；问题多于 3 个时分轮次，按"影响后续决策的深度"排序先问最关键的。
- 同一话题**追问不超过 2 次**；两次后仍无明确答案 → 给候选 + 推荐（规则 2 路径）或请用户明确跳过（规则 3 路径）。
- 用户已给出**明确且有依据**的答案，不得重复确认、不得改写复述后再要一次确认。
- 提问优先用表格/编号列表呈现，让用户可以逐条简短作答。

## 四、结构化审阅（写后停顿的标准）

写完即停时，**禁止**只问"请审阅，是否继续下一步？"。必须先输出**决策点确认清单**，再问去向：

```markdown
✅ {文件} 已生成（路径：{path}）。本文档中我替你做出/记录了以下关键决策与假设：

| # | 决策/假设 | 来源 |
|---|-----------|------|
| 1 | {内容} | 用户明确给出 |
| 2 | {内容} | agent 推断（依据：{一句话}） |
| 3 | {内容} | agent 推荐，待用户确认 |

请逐条确认或纠正（回复编号即可）。全部确认后，是否**继续下一步**（{下一步}）？还是**更新**本层？
```

- "来源"列必须如实区分：用户明确给出 / agent 推断 / agent 推荐待确认。**agent 推断与推荐项是审阅重点**，不许混入"用户明确给出"。
- 用户对任一条提出纠正 → 就地更新当前文档并重发清单，不推进下一步。
