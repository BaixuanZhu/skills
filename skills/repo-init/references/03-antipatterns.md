# 03 · Antipatterns（硬价值）

init 类技能最常见的错误。每条含「✗ 错误做法 → ✓ 正确做法 → 为什么」。
生成 AGENTS.md 前必看——核心价值在"防致命错"。

---

### 1. 为多个工具各建一份记忆
- ✗ 同时生成 `AGENTS.md` + `CLAUDE.md` + `.cursorrules` + `.windsurfrules`。
- ✓ 只产一份 `AGENTS.md`，所有工具自动读取。
- 为什么：多份记忆必然内容漂移（改了一处忘改另一处），且重复维护成本翻倍。AGENTS.md 是社区共识标准，一次生成全工具受益。

### 2. 在 AGENTS.md 里写工具专属 hack
- ✗ 写"用 `@` 引用文件""把规则放 `.cursor/rules`""Claude 请读 `CLAUDE.md`"。
- ✓ 只描述项目事实（命令/约定/架构/硬约束/陷阱），不含任何 agent 或工具专属语法。
- 为什么：AGENTS.md 的护城河是"工具无关、跨工具通用"。混进工具 hack 会破坏通用性，且换个工具即失效。

### 3. 把 AGENTS.md 当 changelog / 团队 wiki
- ✗ 写版本发布记录、更新日志、团队成员介绍、产品 Roadmap。
- ✓ 只写"每个请求都该加载"的高密度上下文；历史与百科放 README/wiki。
- 为什么：内容应信息密集；把 changelog/wiki 堆进去会撑爆行数、稀释信号（Claude Code 黄金实践建议 ≤200 行，非官方硬限）。

### 4. 生成后不 review 直接 commit
- ✗ 写完 `AGENTS.md` 立刻 `git add` + `commit`。
- ✓ 给出草稿 → 用户 review → 用户决定 commit。
- 为什么：自动提交可能把"需核实"的臆造命令、或误读的信号固化进仓库，污染后续所有 AI 会话。

### 5. 忽略已有的 CLAUDE.md
- ✗ 发现 `CLAUDE.md` 存在，仍另起一份 `AGENTS.md` 重复写一遍。
- ✓ 读取 `CLAUDE.md` 内容，合并进 `AGENTS.md`，保留单一事实源。
- 为什么：重复两份记忆会漂移；且 CLAUDE.md 是工具专属，应并入通用载体而非并存。

### 6. 把整份 API 文档塞进去
- ✗ 把每个模块的函数签名、参数表全抄进 AGENTS.md。
- ✓ 只写架构、约定、硬约束、陷阱；API 细节让 AI 直接读代码。
- 为什么：AI 能自行 `Glob`/`Read` 源码；塞文档既撑爆行数又很快过时。

### 7. 写"理想规则"——团队实际不遵守的规范
- ✗ 写"所有函数必须有 JSDoc""禁止 any""提交必须 review"但团队从不执行。
- ✓ 只写 CI 强制项与团队真实遵守的约定。
- 为什么：理想规则会误导 AI 按不存在的标准改代码，引发无谓改动与冲突。

### 8. monorepo 不嵌套子 AGENTS.md
- ✗ 大 monorepo 只在根放一份，子包特殊约定全堆根文件。
- ✓ 子包就近放 `AGENTS.md` 覆盖本目录，根文件管全局（见 `04`）。
- 为什么：根文件膨胀且子包上下文被稀释；嵌套是 AGENTS.md 规范明确支持的层级扩展，仍属同一套通用记忆。

### 9. 命令臆造不经核实
- ✗ 没看 `package.json`，凭印象写 `npm run dev`（实际是 `pnpm dev`）或 `npm test`（实际无该 script）。
- ✓ 命令从构建文件实际提取；无法确认标「需核实」并询问。
- 为什么：误写构建命令比不写更糟——AI 会反复执行失败命令，浪费轮次且误导。

### 10. 写文件树代替架构说明
- ✗ 罗列 `src/ / components/ / utils/ ...` 目录结构。
- ✓ 讲模块职责划分与数据流，不列文件树。
- 为什么：文件树 AI 自己 `Glob` 即得；AGENTS.md 该补的是"为什么这么分""模块间如何协作"这类 AI 看不出的人脑上下文。

### 11. 把敏感信息写进去
- ✗ 写真实 token、密码、内网地址、PII。
- ✓ 只写约定（"用 `.env`""有 `.env.example`"），绝不写明文密钥。
- 为什么：AGENTS.md 通常入库且被多工具读取，泄露即安全风险。

### 12. 一次性生成后不再维护 / 不更新优化
- ✗ 生成一次，依赖版本/结构/CI 大变后仍用旧文件；或发现命令失效也不走更新流程。
- ✓ 把"更新优化"作为一等能力（Path B）：依赖升级、架构调整、CI 规则变更、命令执行报错时，
  重扫仓库信号，对已有 AGENTS.md 做增量更新（C1 流程）。
- 为什么：过期的 AGENTS.md 比没有更危险——持续向 AI 提供错误信号。本技能核心价值之一是"已有时也要安全更新优化"。

### 13. 更新时整份覆盖重写已有文件
- ✗ 用户已有 AGENTS.md，仍生成一份全新内容整份覆盖，丢弃用户手写的有效约定与项目特有背景。
- ✓ 走 Path B 增量更新：逐 section 比对现状信号，标注「过期/缺失/仍准确」，
  只改需要改的，保留用户原有有效内容；给出 diff 式修订建议 + 修订后完整草稿。
- 为什么：用户手写内容往往含 AI 扫不出的"人脑上下文"（如政治/合规约束、历史坑）；整份覆盖会
  丢失这些信息且易引发抵触。增量 diff 才是"更新优化"而非"推倒重来"。

### 14. 把待办 / 未决 / 任务执行进度写进 AGENTS.md
- ✗ 写"- [ ] 待实现：XX 功能"、"未决：用 A 还是 B 方案？"、"当前进度：已完成 3/5"、"本周 TODO"、"已修复登录 bug"。
- ✓ 只写"每次对话都必须得知的、稳定的上下文与约定"（命令/约定/架构/硬约束/陷阱）；待办/未决/进度属于任务执行态，留在 issue / 看板 / 本次会话上下文，不进 AGENTS.md。
- 边界（不要写进 AGENTS.md）：待办 / TODO 清单、未实现功能列表、未决问题（"用 A 还是 B？"）、当前任务进度 / 完成百分比 / 本周计划、本次或历史会话"做了什么"的执行记录、会议纪要 / 临时讨论结论、明文 token / 密码 / 内网地址 / PII。写入门槛：不知道这条是否会在**本次对话**出错或做错决策，就别写。
- 为什么：AGENTS.md 应是无状态、低频更新的稳定文档；塞入任务进度会让它变成高频过期状态日志——AI 每次加载都读到过期/不正确的"当前状态"，反而误导。它是对"新同事"的背景说明，不是给"项目经理"的进度周报。

### 15. 无界扫描 / 全文 Read 导致 Token 爆炸与上下文污染
- ✗ 用 `Glob("**/*")` 或全目录 `Grep` 递归 `node_modules` / `dist`；为"看一眼结构"全量 `Read` 长文件；
  更新阶段对未变更文件重复全量重扫。
- ✓ 遵守 `01` §0 **Token 经济学铁律**：限定搜索范围（铁律 1）、元数据优先（铁律 2）、懒加载读取（铁律 3）、
  Bash 一次聚合（铁律 4）、签名提取（铁律 5）、Path B 走 Git 增量（铁律 6）、信号先聚后出（铁律 7）。
- 为什么：无界扫描几分钟内撑爆上下文、造成 Context Rot 与高额 Token 成本，让 Agent 在噪音中迷失真信号。Token 利用率是初级与高级 Agent 的分水岭。
